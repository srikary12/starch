# Starch wire contract — `v1`

This is the interface between a native shell and `starchd`. The macOS shell in
`apps/macos/` is one consumer; Windows and Linux shells will be others. Treat
this document as the source of truth — if the daemon and this file disagree,
that is a bug in one of them.

**Status legend.** Each endpoint is marked with the milestone that lands it.
Endpoints marked *planned* are documented so shell authors can build against
the shape, but the daemon returns `404 not_found` for them today.

---

## 1. Transport

HTTP/1.1 over a **Unix domain socket**. There is no TCP listener, on any port,
ever. This is deliberate: the daemon holds the user's API key in memory, and a
loopback port is reachable by every process on the machine.

| | |
|---|---|
| Socket path | `$SOCKET` (see [§6](#6-process-contract)), default `~/Library/Application Support/Starch/starchd.sock` on macOS |
| Socket mode | `0600`, inside a `0700` directory |
| HTTP version | 1.1, keep-alive expected |
| `Host` header | Ignored. Send anything; `starchd` is conventional. |
| Encoding | UTF-8 throughout. Request and response bodies are JSON unless stated otherwise. |

### Path length

`sun_path` is capped at 104 bytes on macOS and 108 on Linux. `starchd` refuses
a socket path longer than 103 bytes with a readable error rather than letting
`bind` fail with `EINVAL`. Shells should keep the path short.

### Windows

Windows 10 1803+ supports `AF_UNIX`, so the intent is that a Windows shell uses
the same transport with no contract change. Named pipes are the fallback if
that turns out not to hold. There is no abstraction layer for this yet and
none should be added until a second platform actually needs it.

## 2. Authentication

Every request must carry the handshake token:

```
Authorization: Bearer <token>
```

The token is generated by the shell at spawn and handed to the daemon via the
`STARCH_TOKEN` environment variable. It is compared in constant time. The
scheme name is case-insensitive; the token is not.

A missing or wrong token gets `401` with code `unauthorized`. Authentication
runs **before** routing, so an unauthenticated caller cannot map the route
table by watching `401` and `404` diverge.

### What the token is and is not for

The `0600` socket already restricts access to processes running as the user who
started the daemon. The token is defence in depth against another of that
user's own processes stumbling onto the socket — a stale shell, a second copy
of the app, a script.

It is **not** a defence against an attacker already running as the user. They
can read the daemon's environment with `ps -E`. If that threat matters to you,
the mitigation is to not have hostile code running under your account.

## 3. Error envelope

Every non-2xx response has this body, including routing and method errors:

```json
{ "error": { "code": "not_found", "message": "no such endpoint: /v1/nope" } }
```

`code` is stable and machine-readable; switch on it. `message` is for display
and may be reworded at any time.

| Code | HTTP | Meaning |
|---|---|---|
| `unauthorized` | 401 | Missing or invalid handshake token. |
| `not_found` | 404 | No such endpoint. |
| `method_not_allowed` | 405 | Route exists, wrong method. Response carries `Allow`. |
| `not_implemented` | 501 | Reserved: route is in the contract but unavailable in this build. |

Codes for provider failures (auth, rate limits, upstream errors) are defined in
[§5](#5-planned-endpoints) and land with M2.

## 4. Implemented endpoints

### `GET /healthz` — liveness and handshake check *(M0)*

The shell calls this immediately after spawn to confirm the handshake, then on
a timer as a heartbeat. The heartbeat is load-bearing: it is what resets the
daemon's idle-exit timer.

**Response `200`**

```json
{
  "status": "ok",
  "name": "Starch",
  "version": "0.1.0",
  "api_version": "v1",
  "pid": 4711,
  "uptime_ms": 128
}
```

| Field | Notes |
|---|---|
| `status` | `"ok"` whenever the daemon answers. Reserved for a future degraded state. |
| `name` | Product name; lets a shell confirm it reached the daemon it expected. |
| `version` | Daemon build version. |
| `api_version` | Contract version served. A shell that does not recognise it should refuse to proceed rather than guess. |
| `pid` | Lets the shell verify the answering process is the one it spawned, and reap it if not. |
| `uptime_ms` | Milliseconds since daemon start. |

## 5. Planned endpoints

Documented for shell authors. Not served yet.

### `POST /v1/session` — hand over provider credentials *(M2)*

The shell reads the API key from the OS secret store and posts it here. The
daemon holds it **in memory only** and never writes it to disk or to a log.
`starchd` has no access to any platform secret store, by design: each shell
uses its own native one and the contract stays identical.

```json
{
  "provider": "anthropic",
  "model": "claude-sonnet-5",
  "base_url": "https://api.anthropic.com",
  "api_key": "sk-..."
}
```

`provider` is `anthropic` or `openai_compatible`. `base_url` is optional for
`anthropic` and required for `openai_compatible` (OpenAI, OpenRouter, Groq,
Together, Ollama, LM Studio).

### `POST /v1/rewrite` — stream a rewrite *(M2)*

```json
{ "text": "...", "preset": "concise", "hint": "optional freeform steer" }
```

Responds `200` with `Content-Type: text/event-stream`. See [§7](#7-sse-framing).

Cancellation is part of the contract: when the user presses Esc the shell
closes the connection, and the daemon must cancel the upstream provider call
rather than letting the generation run on and bill the user.

### `POST /v1/accept` — record an accepted rewrite *(M4)*

```json
{ "original": "...", "final": "...", "preset": "concise" }
```

Feeds the local voice profile. Never leaves the machine.

### `GET /v1/presets`, `PUT /v1/presets` *(M3)*

Read and replace the preset set, backed by
`~/Library/Application Support/Starch/presets.json`.

## 6. Process contract

The shell owns the daemon's lifetime. The daemon is spawned at app launch, not
on first use — cold-starting a process while the user waits spends latency the
product does not have.

### Environment

| Variable | Required | Meaning |
|---|---|---|
| `STARCH_TOKEN` | **yes** | Handshake token. The daemon exits non-zero at startup if unset. |
| `STARCH_SOCKET` | no | Socket path. Defaults to the per-user application-support directory. |
| `STARCH_IDLE_TIMEOUT` | no | Go duration. Default `30s`. `0` disables idle exit. |
| `STARCH_DEBUG` | no | Verbose timing logs on stderr. |

### Shutdown

The daemon exits on any of these, and unlinks its socket on the way out:

1. `SIGINT` / `SIGTERM` — the normal path. The shell sends this on quit.
2. **Orphaned** — the parent PID changed, so the shell died without cleaning
   up. Checked every 2s.
3. **Idle** — no request within `STARCH_IDLE_TIMEOUT`. A request that is still
   streaming counts as activity, so a long rewrite is never cut short.

Exit code is `0` for all three; non-zero means a real failure.

Layers 2 and 3 exist because an orphaned daemon sitting in memory holding
someone's API key is a bug, not an inconvenience. A shell must still terminate
the daemon explicitly — the backstops are not the mechanism.

### Stale sockets

On startup the daemon probes an existing socket file. If something answers, it
refuses to start rather than stealing the address from a live daemon. If
nothing answers, it removes the file and binds. A non-socket file at that path
is never removed.

## 7. SSE framing

*(Lands with M2; specified here because it is the part shells most need to
agree on.)*

Standard `text/event-stream`. Each event is a `data:` line carrying a JSON
object, terminated by a blank line.

```
data: {"delta":"Thanks for "}

data: {"delta":"the update"}

data: {"done":true,"full":"Thanks for the update","usage":{"input_tokens":42,"output_tokens":9}}

```

- Exactly one terminal event, carrying `done: true`.
- `full` is the complete rewrite. Clients should prefer it over their own
  concatenation of deltas.
- An error mid-stream arrives as `data: {"error":{"code":"...","message":"..."}}`
  and ends the stream. The HTTP status is already `200` by then, so clients
  must handle in-band errors, not just status codes.

**Implementation note for shell authors:** parse with a reader that has no line
length cap. Go's `bufio.Scanner` defaults to a 64 KB token limit and truncates
silently past it; the daemon uses `bufio.Reader` for exactly this reason. Test
against events split mid-chunk across reads — that is the bug that ships
otherwise.

## 8. Versioning

The version lives in the path (`/v1/...`). Within `v1`:

- **Allowed:** adding endpoints, adding optional request fields, adding
  response fields. Clients must ignore unknown response fields.
- **Not allowed:** removing or renaming fields, changing a field's type,
  changing an error `code`, tightening validation on an existing field.

Anything in the second list means `/v2` and a `api_version` bump in `/healthz`.
